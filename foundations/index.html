Learning path 01

Foundations

What do we need to understand before choosing a data structure or technique?

We start with the ideas that make later code easier to reason about: how data is represented, how abstractions protect us from implementation details, and how to measure the cost of a solution.

Start here

Build the mental models first.

Before working through arrays, linked lists, or a sliding-window technique, it helps to understand the questions underneath the implementation:

  • What operations does this data need to support?
  • Which representation makes those operations clear?
  • What does the solution cost as the input grows?
  • Which details should the rest of the program be allowed to depend on?

Core ideas

The foundations we will use.

  • Data abstraction, constructors, selectors, and representation choices
  • Time and space complexity as tools for comparing solutions
  • Recursion, invariants, and tracing state through a program
  • Abstraction barriers that let implementation change without changing use

Next step

Put the ideas to work.

The current sequence-based work applies these ideas to arrays and linked lists, then to linked-list traversal, sliding-window, and two-pointer techniques.
