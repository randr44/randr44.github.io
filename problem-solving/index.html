Learning path 04

Problem solving

A guide to turning an unfamiliar problem into a sequence of smaller, testable decisions.

Patterns are useful when they explain a constraint. The goal here is to recognize that constraint, choose the smallest useful state, and make the reasoning visible before optimizing the code.

The process

Understand the problem before reaching for a pattern.

  1. Restate the input, output, and constraints in plain language.
  2. Work through a small example by hand, including an edge case.
  3. Identify what changes, what stays true, and what information is missing.
  4. Choose a representation that makes the next operation cheap.
  5. Trace the solution, then measure its time and space cost.

Study sequence

Patterns to recognize.

01 · Count and lookup Frequency maps and sets Trade repeated searching for constant-time lookup
02 · Range state Prefix sums and difference tracking Precompute relationships so range questions become simple
03 · Ordered movement Two pointers and sliding window Move through a sequence while preserving a useful invariant
04 · Choice and search Greedy decisions and binary search Use a local choice or an ordered search space when it is justified
05 · Explore and undo Recursion and backtracking Represent a decision tree and restore state after each branch
06 · Reuse subproblems Dynamic programming Define state, transition, base case, and the work worth remembering

For every future note

Make the reasoning inspectable.

A finished note should show the first naive idea, the constraint it fails on, the pattern that addresses that constraint, and a trace that a reader can follow line by line.

Only then should it compare complexity and discuss whether the extra state or preprocessing is worth the cost.
