Learning path 02

Data structures

A study guide for choosing how data should be represented, changed, and accessed.

A data structure is a set of decisions about organization and operations. The useful question is not which structure is best in general, but which operations the program needs to make cheap and clear.

The questions

Choose the operations before the structure.

  • Which values belong together, and how are they related?
  • Do we need fast lookup, ordered access, insertion, or removal?
  • What must remain true after each operation?
  • What memory and time costs are acceptable as the input grows?

Study sequence

Structures to build and compare.

01 · Contiguous storage Arrays and dynamic arrays Fast indexed access with resizing and shifting tradeoffs
02 · Linked storage Singly and doubly linked lists References, traversal, insertion, deletion, and edge cases
03 · Restricted access Stacks and queues Simple interfaces built around last-in or first-in behavior
04 · Keyed access Hash tables Map keys to values while reasoning about collisions and load
05 · Hierarchical order Trees and heaps Represent hierarchy, priority, and ordered operations
06 · Relationships Graphs Model connections and prepare for traversal and shortest paths

For every future note

Make the structure’s promises explicit.

Each finished note will define the representation, name its invariants, implement the core operations, and test the boundaries where the structure is empty, full, or contains one element.

Then it will compare the structure with a practical alternative so the tradeoff is visible instead of implied.
